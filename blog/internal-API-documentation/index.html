Internal API documentation

Your team builds APIs daily, but frontend devs are still confused and backend devs are frustrated. The problem isn't skills — it's communication.

Internal API docs bridge the gap between what backend builds and what frontend actually needs.

🚨 The problem

Classic scenario:

  • Backend builds /api/users
  • Frontend assumes it returns user preferences
  • Actually returns basic profile only
  • Frontend breaks, Slack explodes 💥

Root cause: Backend thinks in data structures, frontend thinks in UI components.

🎯 What makes internal docs different

External docs explain how to use your API. Internal docs explain why it exists and how frontend uses it.

🏗️ What to include

1. Business context 💼

## User Profile API
Powers the dashboard and settings page. Frontend needs this to show
user info and handle profile updates.

2. Frontend-friendly examples 🎨

Show what components actually get:

// What you receive
{
  "id": "123",
  "name": "Maria Perez",
  "email": "maria@example.com",
  "plan": "pro"
}

// How it's used
<h1>Welcome, {user.name}!</h1>
<span className="badge">{user.plan}</span>

3. Data flow 🔄

Map the complete journey:

User clicks save → POST /api/users → Backend validates →
Returns updated user → Frontend updates UI

4. Common gotchas 🚨

⚠️ Important Notes:
- All timestamps in UTC
- Returns 404 if user doesn't exist
- Users can only see their own data

🛠️ Simple tools

  • README in repo 📁 — Keep it close to code
  • Notion page 📝 — For detailed context
  • Slack channel 💬 — Quick API questions

📋 Quick template

# [Feature] API

## 🎯 Purpose
Brief business reason (e.g., powers profile page)

## 🔗 Key Endpoints
- `GET /users/:id` → Profile component
- `PUT /users/:id` → Settings form

## 📝 Example Response
{
  "id": "123",
  "name": "Maria Perez"
}

## ⚠️ Notes
- Auth required
- Returns 404 if not found

## 🔄 Recent Changes
- Added avatar field (2024-01-15)

💡 Best practices

  1. Show real component usage — not abstract examples
  2. Document state changes — pending → active → suspended
  3. Add debugging tips — expired tokens, edge cases
  4. Update when things break — immediately

🏆 Bottom line

Internal docs aren't about perfection — they prevent the 10th "how does this work?" Slack message.

Good internal docs:

  • Save time on both sides ⏳
  • Reduce communication bugs 🐛
  • Make onboarding easier 🚀

Spend 30 minutes documenting that tricky endpoint. Save hours of confusion later! 🙌
