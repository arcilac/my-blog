SQL JOINs: The ultimate guide to connecting your data

When working with multiple tables, you often need to join rows based on a relationship (like users.id = orders.user_id). That's where JOINs come in.

But the trickiest part is usually: what happens when there's no match? Let's explore INNER, LEFT, RIGHT, and FULL JOINs, and see how NULLs appear in each case.

You can try all of these examples yourself at 👉 pg-sql.com.

🧠 Example setup

-- Users table
CREATE TABLE users (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    email VARCHAR(100)
);

-- Orders table
CREATE TABLE orders (
    id INT PRIMARY KEY,
    user_id INT,
    product VARCHAR(50),
    amount DECIMAL(10,2),
    order_date DATE
);

-- Sample data
INSERT INTO users (id, name, email) VALUES
(1, 'Alice', 'alice@mail.com'),
(2, 'Bob', 'bob@mail.com'),
(3, 'Charlie', 'charlie@mail.com'); -- No orders

INSERT INTO orders (id, user_id, product, amount, order_date) VALUES
(101, 1, 'Laptop', 1200.00, '2024-01-15'),
(102, 2, 'Phone', 800.00, '2024-01-20'),
(103, 1, 'Mouse', 25.00, '2024-02-05'),
(104, NULL, 'Gift Card', 50.00, '2024-02-10'); -- Order with no user

Notice:

  • Charlie has no orders.
  • There's an order (Gift Card) with no user (user_id = NULL).

📌 INNER JOIN

SELECT u.name, o.product, o.amount
FROM users u
INNER JOIN orders o ON u.id = o.user_id;

Result:

text
name  | product | amount
------|---------|--------
Alice | Laptop  | 1200.00
Bob   | Phone   | 800.00
Alice | Mouse   | 25.00

✅ What happened:

  • Only rows where u.id = o.user_id and neither side is NULL.
  • Charlie disappears (no orders).
  • The Gift Card order disappears (no valid user).

👉 Rule: INNER JOIN excludes non-matching rows.

📌 LEFT JOIN

SELECT u.name, o.product, o.amount
FROM users u
LEFT JOIN orders o ON u.id = o.user_id;

Result:

text
name    | product | amount
--------|---------|--------
Alice   | Laptop  | 1200.00
Alice   | Mouse   | 25.00
Bob     | Phone   | 800.00
Charlie | NULL    | NULL

✅ What happened:

  • All users appear.
  • If they don't have matching orders, order fields are NULL.
  • Charlie shows up with NULL in product and amount.
  • The Gift Card order is not included, because LEFT JOIN prioritizes the left table (users).

👉 Rule: Keep all left rows, fill unmatched right columns with NULL.

📌 RIGHT JOIN

SELECT u.name, o.product, o.amount
FROM users u
RIGHT JOIN orders o ON u.id = o.user_id;

Result:

text
name  | product   | amount
------|-----------|--------
Alice | Laptop    | 1200.00
Bob   | Phone     | 800.00
Alice | Mouse     | 25.00
NULL  | Gift Card | 50.00

✅ What happened:

  • All orders appear.
  • If they don't have a matching user, user fields are NULL.
  • Alice and Bob's orders match.
  • The Gift Card order appears with NULL in name.
  • Charlie disappears (he had no orders).

👉 Rule: Keep all right rows, fill unmatched left columns with NULL.

📌 FULL OUTER JOIN

SELECT u.name, o.product, o.amount
FROM users u
FULL JOIN orders o ON u.id = o.user_id;

Result:

text
name    | product   | amount
--------|-----------|--------
Alice   | Laptop    | 1200.00
Bob     | Phone     | 800.00
Alice   | Mouse     | 25.00
Charlie | NULL      | NULL
NULL    | Gift Card | 50.00

✅ What happened:

  • All users + all orders, no matter what.
  • Charlie appears with NULL order info.
  • The Gift Card order appears with NULL user info.

👉 Rule: Keep everything from both sides, filling missing matches with NULL.

⚖️ Quick comparison

JOIN TypeKeeps Users w/o Orders?Keeps Orders w/o Users?NULLs Appear In
INNER❌ No❌ NoNone (only matches)
LEFT✅ Yes❌ NoOrder fields (when no match)
RIGHT❌ No✅ YesUser fields (when no match)
FULL✅ Yes✅ YesBoth sides (depending on missing match)

🧪 Why NULLs matter

The NULLs tell you which rows didn't find a match:

  • NULL on the order side (LEFT JOIN) → user without orders.
  • NULL on the user side (RIGHT JOIN) → order without a valid user.
  • NULLs on both sides (FULL JOIN) → a complete picture of mismatches.

This is why JOINs are so powerful: they let you not only combine data but also detect missing relationships.

📎 Final thoughts

  • Use INNER JOIN when you only care about matches.
  • Use LEFT JOIN to keep all users, even if they have no orders.
  • Use RIGHT JOIN to keep all orders, even if some don't belong to a user.
  • Use FULL JOIN for a complete view, including all mismatches.

Mastering JOINs is about mastering NULLs — they show you what's missing in your relationships.
